# SC'26 IA^3 Artifact Evaluation

This artifact reproduces the GPU experiments underlying the paper's primary
performance and portability claims.

## Artifact Description

### Scope

The artifact consists of the CUDA/C++ Bloom filter implementation, the
paper-specific benchmark configurations, the GPU CBF and WarpCore baselines, a
random-access GUPS benchmark, and scripts for building, executing, and
normalizing the results. No external datasets are required; all input keys are
generated by the benchmarks.

### Availability

- Canonical development branch:
  `https://github.com/NVIDIA/cuCollections/tree/bloom-filter-ia3-artifact`
- Frozen artifact release:
  `https://github.com/sleeepyjack/cuCollections/releases/tag/ia3-2026-artifact-v1.0`
- License: Apache License 2.0.

The automated workflow covers the following results:

| Paper result | Artifact evidence |
| --- | --- |
| Throughput and false-positive-rate trade-offs across SBF vectorization layouts and block sizes | `sbf.json`, `normalized_results.csv`, and `best_results.csv` |
| Comparisons with WC BBF, GPU CBF, and GPU CSBF | `warpcore.json`, `cbf.json`, `csbf.json`, and the normalized result tables |
| Efficiency relative to random-access GPU memory throughput | `gups.csv` and `sol_efficiency.csv` |
| Performance portability across GPU architectures | Independent `full` runs on B200, H200, and RTX PRO 6000 GPUs |

### Expected Results

Exact throughput depends on GPU clocks, driver version, system load, and
whether the GPU is used exclusively. The expected result is therefore
agreement in trends and relative behavior rather than bitwise-identical
throughput:

- Valid SBF layouts should show that the preferred balance of horizontal and
  vertical vectorization depends on the operation, block size, and GPU
  architecture.
- Fully horizontal layouts should generally perform best for construction,
  while lookup should favor fewer cooperating threads for smaller blocks.
- For 1 GiB filters, the best SBF configurations with blocks up to 256 bits
  should approach the machine-local random-access bounds measured by GUPS.
- For 32 MiB filters, the optimized SBF should substantially outperform WC BBF
  at comparable false-positive rates and deliver much higher throughput than
  the more accurate GPU CBF.
- GPU CSBF configurations should expose the expected throughput versus
  false-positive-rate trade-off at larger block sizes.

Invalid combinations of compile-time layout parameters are reported as
skipped benchmark states and are excluded from `best_results.csv`.

### Workloads and Measurements

All benchmarks use deterministic sequences of unique 64-bit integer keys. The
hash functions transform these keys into the filter's irregular access
patterns; no input files or random seeds are required.

The paper-scale run uses \(N=10^9\) operations, 64-bit filter words,
\(k=16\) fingerprint bits, block sizes from 64 to 1024 bits, and 32 MiB and
1 GiB filter allocations. SBF benchmarks sweep all valid combinations of the
horizontal parameter \(\Theta\) and vertical parameter \(\Phi\). CSBF
benchmarks additionally sweep the valid group counts \(z\).

Construction timing includes every insertion and excludes filter clearing.
False-positive rates are measured outside the timed lookup region at a fixed
space budget of \(c=m/n=2k=32\) bits per key. Each filter is populated with
\(n=m/(2k)\) distinct keys before querying a disjoint sequence of \(N\) keys.

NVBench determines the measurement repetitions and reports both mean GPU time
and relative noise. The `--profile` option used by the smoke evaluation reduces
the measurement duration and is intended for functional validation, not
quantitative comparison.

### Expected Reproduction Time

Approximate times depend on network and host performance:

- Container download and first build: 10 to 30 minutes.
- Smoke evaluation after setup: less than 5 minutes.
- Full evaluation: approximately 15 to 60 minutes per GPU.
- Result normalization and summary generation: less than 1 minute.

The paper-scale benchmark execution on a B200 completed in approximately 17
minutes, excluding container download and compilation.

## Artifact Evaluation

### Obtain the Artifact

During development, clone the artifact branch:

```bash
git clone \
  --branch bloom-filter-ia3-artifact \
  --single-branch \
  https://github.com/NVIDIA/cuCollections.git
cd cuCollections
```

The final appendix will reference the archived release and DOI instead of the
mutable branch.

### Workflow

The evaluation consists of the following dependent tasks:

1. **Prepare:** obtain the pinned container and dependencies, then compile the
   benchmarks and correctness tests.
2. **Validate:** run the Bloom-filter tests and a reduced benchmark matrix.
3. **Measure:** run the paper-scale SBF, CSBF, WC BBF, GPU CBF, and GUPS
   experiments.
4. **Analyze:** normalize the raw NVBench output and generate the comparison
   tables and human-readable summary.
5. **Archive:** package the complete result directory and its checksum.

### Functional Evaluation

Run the reduced smoke evaluation:

```bash
artifact/run_in_docker.sh smoke
```

This builds and runs the Bloom-filter unit tests, executes all four benchmark
implementations with a reduced workload, runs the GUPS benchmark, and
generates normalized output. Successful completion without test, benchmark, or
script errors establishes that the artifact is functional.

### Paper-Scale Evaluation

Run the complete benchmark matrix:

```bash
artifact/run_in_docker.sh full
```

The full run uses \(10^9\) input keys and 32 MiB and 1 GiB filters. It evaluates:

- GPU SBF construction and lookup across all valid vectorization layouts.
- GPU CSBF construction and lookup across valid group and layout parameters.
- WC BBF construction and lookup for each tested block size.
- GPU CBF construction and lookup.
- Random-read and random-write GUPS bounds.

To reproduce the architecture comparison, execute the full workflow separately
on each target GPU and retain each result directory.

### Compute Nodes Without Network Access

Preparation does not require a GPU or the NVIDIA Container Toolkit. On a
networked login or build node, provide the CUDA architecture of the GPU that
will execute the benchmarks:

```bash
# B200: 100, H200: 90, RTX PRO 6000: 120
artifact/run_in_docker.sh prepare 100
```

This downloads and builds all dependencies and the GUPS benchmark under
`build/ia3-artifact-docker`. The checkout can then be used from an air-gapped
compute node:

```bash
CUDA_ARCHITECTURES=100 artifact/run_in_docker.sh full
```

The Docker image must also be available on the compute node. If login and
compute nodes use separate Docker image stores, transfer the pinned image with
`docker save` and `docker load`, or use the site's container-image mirror.

### Existing CUDA Environment

To run directly in an existing CUDA environment:

```bash
artifact/run_benchmarks.sh
```

For a short functional run:

```bash
NUM_INPUTS=1000000 FILTER_SIZES=32 artifact/run_benchmarks.sh --profile
```

### Output and Analysis

Docker runs write their results to
`build/ia3-artifact-results/<smoke|full>`. Direct runs use
`build/ia3-artifact-results` by default. Each result directory contains:

- `sbf.json` and `sbf.csv`: complete SBF layout sweep.
- `csbf.json` and `csbf.csv`: CSBF configurations.
- `warpcore.json` and `warpcore.csv`: WC BBF baseline.
- `cbf.json` and `cbf.csv`: GPU CBF baseline.
- `gups.csv`: machine-local random-read and random-write throughput bounds.
- `bloom_filter_tests.log`: output from the Bloom-filter correctness suite.
- `normalized_results.csv`: all implementations represented by a common
  schema.
- `best_results.csv`: highest-throughput layout for each implementation,
  operation, filter size, block size, and CSBF group count.
- `comparisons.csv`: SBF/WC BBF, SBF/GPU CBF, and best-CSBF/SBF throughput
  ratios calculated from the current run.
- `sol_efficiency.csv`: best 1 GiB SBF throughput divided by the corresponding
  machine-local GUPS bound for blocks up to 256 bits.
- `summary.md`: human-readable summary of the best layouts, implementation
  comparisons, and speed-of-light efficiency.
- `metadata.json`: source revision, software environment, GPU, benchmark
  parameters, and timestamp.
- `gpu_state_before.csv` and `gpu_state_after.csv`: clock, power, temperature,
  and memory snapshots.
- `gpu_telemetry.csv`: periodic clock, power, temperature, and memory samples
  collected during benchmark execution.
- `run.log`: complete build, test, and benchmark log.

Use `normalized_results.csv` to reconstruct the throughput versus
false-positive-rate frontier and layout tables. Use `best_results.csv` for
comparisons between implementations and `sol_efficiency.csv` for the
speed-of-light analysis. Across different GPUs, compare the corresponding
`best_results.csv` and `sol_efficiency.csv` files.

Performance values need not exactly match the paper on different systems.
Relevant agreement consists of the same broad throughput ordering, similar
preferred layouts, and comparable efficiency relative to the local GUPS
measurement. Large discrepancies should first be checked against
`metadata.json`, GPU exclusivity, clock behavior, and thermal or power limits.

### Packaging Results

Package a complete result directory for sharing or archival with:

```bash
artifact/package_results.sh build/ia3-artifact-results/full
```

This creates a compressed archive and a corresponding SHA-256 checksum beside
the result directory.

### Configuration

The workflow accepts the following environment variables:

- `BUILD_DIR`: CMake build directory.
- `OUTPUT_DIR`: benchmark output directory.
- `NUM_INPUTS`: number of input keys.
- `FILTER_SIZES`: comma-separated filter sizes in MiB.
- `CUDA_ARCHITECTURES`: CMake CUDA architecture value.
- `JOBS`: parallel build jobs.
- `DEVICE`: NVBench logical device ID; defaults to `0`.
- `GUPS_LOGN`: base-2 table-size exponent; defaults to `27` (1 GiB).
- `GUPS_REPEATS`: GUPS kernel repetitions; defaults to `5`.
- `GUPS_ACCESSES_PER_ELEMENT`: random accesses per thread; defaults to `32`.
- `GUPS_GPU_ARCH`: CUDA architecture for the GUPS binary; detected by default.
- `GPU_TELEMETRY_INTERVAL`: seconds between telemetry samples; defaults to `5`,
  or set to `0` to disable continuous sampling.
- `NVIDIA_SMI_DEVICE`: physical GPU index or UUID used for diagnostics during
  direct runs. Set this when `CUDA_VISIBLE_DEVICES` remaps CUDA device ordinals.
- `SOURCE_COMMIT`: source revision fallback when Git metadata is unavailable.

Additional arguments are forwarded to every NVBench executable.

On shared systems, the Docker launcher exposes only one GPU. By default, it
uses the UUID of the first GPU visible through `nvidia-smi`; this avoids
interpreting a Slurm-local `CUDA_VISIBLE_DEVICES` ordinal as a host GPU index.
Set `GPU_DEVICE` to an explicit host GPU index or UUID when required. Inside
the container, the selected GPU is logical device `0`.

### Troubleshooting

- **Docker permission denied:** Ensure the current user can access the Docker
  daemon, or follow the existing-CUDA-environment instructions instead.
- **No GPU is visible:** Verify that `nvidia-smi` works in the allocation and
  that NVIDIA Container Toolkit is configured. Set `GPU_DEVICE` for Docker GPU
  selection or `NVIDIA_SMI_DEVICE` for diagnostics during a direct run.
- **`no kernel image` or unsupported architecture:** Re-run preparation with
  the compute capability of the target GPU and use the same value for
  `CUDA_ARCHITECTURES` during execution.
- **A compute node attempts a download:** Run `prepare` on a networked node
  first and ensure the checkout, including `build/ia3-artifact-docker`, is
  available at the same path on the compute node.
- **Out of device memory:** Run the smoke evaluation first. Reducing
  `NUM_INPUTS` is suitable for functional testing but no longer reproduces the
  paper-scale workload.
- **Unexpectedly low or noisy throughput:** Inspect `gpu_telemetry.csv` and the
  before/after state files for clock, thermal, power, or memory pressure.
- **Empty `sol_efficiency.csv`:** The GUPS allocation must match a tested filter
  size. This is expected for the 32 MiB-only smoke evaluation because the
  default GUPS table is 1 GiB.
